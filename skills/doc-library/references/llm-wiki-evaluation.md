# LLM Wiki 構想用於法務文件的評估

## 來源與日期

- 評估對象：Andrej Karpathy 的「LLM Wiki」構想文，https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f 。2026-10-07 以 `curl` 讀取全文。交辦說明發表於 2026-04；gist 原文內容未載日期，發表日期未另行查證。
- 原文自述為「刻意抽象」的構想文，所有元件「皆為選用、可模組化」。本評估對象是構想本身，不是任何特定實作。
- 以下「原文」指該構想文；標「推論」者為本評估的判斷，不是原文或實測結果。

## 原文的核心構想

三層：原始資料（不可變，LLM 只讀）、由 LLM 撰寫並維護的 wiki（摘要頁、實體頁、概念頁、綜合頁）、schema 檔（規定結構與作業流程，如 CLAUDE.md）。三種操作：ingest（讀入新來源，更新 wiki 多個頁面，一份來源可能牽動 10 至 15 頁）、query（讀 wiki 作答，好答案可存回 wiki）、lint（找矛盾、被新資料取代的敘述、孤兒頁、缺漏的交叉引用）。兩個特殊檔：`index.md`（內容目錄）與 `log.md`（依時間追加的紀錄，條目前綴一致以便 grep）。原文主張的價值是知識「編譯一次、持續更新」，而不是每次查詢都從原始文件重新推導。

## 逐項評估

| 元件 | 結論 | 理由 |
|---|---|---|
| 原始資料不可變 | 採用，並加強 | 法務文件的唯一依據必須不被改動。本 skill 要求原檔唯讀，並以 sha256 偵測變動 |
| schema 檔 | 採用 | `SKILL.md` 扮演此角色，規定結構、流程與禁止事項，使每次作業行為一致 |
| index.md | 採用，改由腳本產生 | 原文由 LLM 維護目錄。目錄有誤會使查詢漏掉文件（推論），改由腳本依 frontmatter 重建，結果固定、可測試 |
| log.md | 採用，改由腳本追加 | 採用原文的一致前綴格式；由腳本追加，避免 LLM 漏記 |
| lint | 採用，分兩層 | 過期、孤兒、缺欄、頁碼標記等可機械判定的項目交給腳本；矛盾與語意檢查由 Claude 判讀，結果標為「疑似」並附雙方原文出處 |
| ingest 時更新多個 wiki 頁面 | 不採用 | 一份來源牽動 10 至 15 頁，代表一次轉錄錯誤會同時進入多頁（推論）。本 skill 的 ingest 只產生衍生 Markdown 與業務欄位，並要求抽查 |
| LLM 撰寫並維護的摘要頁、實體頁、概念頁 | 限縮為導覽 | 見下節 |
| 答案存回 wiki 並持續累積 | 不自動採用 | 答案若成為後續查詢的依據，錯誤會被引用與放大（推論）。使用者要求保存時才寫入主題頁，且須符合引用規則 |
| 「編譯一次、不再重新推導」 | 不採用 | 對法務而言，每次查詢回原文核對是需要的成本，不是缺點 |
| 搜尋工具（原文提及 qmd） | 暫不評估 | 目前以 index 加 grep 即可；文件量大到不夠用時再另行評估，未查證該工具 |

## 為什麼摘要頁只作導覽

法務文件的風險集中在細節：金額、日期、期間、當事人、「得」與「應」的差別、但書。LLM 撰寫的摘要頁有以下風險（推論，依 LLM 一般特性與原文流程推得，未以本專案資料實測）：

1. 誤寫：摘要可能把「得終止」寫成「應終止」，或漏掉但書，且文字讀來流暢，不易被察覺。
2. 漂移：原文流程讓 wiki 頁面隨新來源反覆改寫，多輪之後頁面與原文的距離增加，且沒有逐字對照的錨點。
3. 錯誤自我強化：後續的 ingest 與 query 讀的是 wiki，而不是原文，錯誤會被引用到更多頁面。
4. 責任：使用者是最終把關者，需要能在原文找到每一個結論。無出處的摘要無法被核對。

因此本 skill 的做法：

- 摘要頁、主題頁只放文件清單、指向原文頁碼的連結與原文逐字引文；陳述一律附出處。
- 任何要告訴使用者的結論，先回原文核對。
- 主題頁記錄所依據的來源檔 sha256，原檔變動後視為過期。
- 衍生 Markdown 與業務欄位附 `evidence` 與驗證狀態，掃描檔的 OCR 文字另有「待對照影像」狀態。

## 與原文的主要差異

| 項目 | 原文 | 本 skill |
|---|---|---|
| 知識的所在 | wiki，由 LLM 維護 | 原文；wiki 只作導覽 |
| 作業中人的角色 | 可選（原文提到「保持參與」，也說可低監督批次處理） | 必要：抽查、對照、最終判斷 |
| index、log | LLM 維護 | 腳本產生 |
| 矛盾 | 由 LLM 標記並反映在綜合結論 | 並列原文出處，不調和 |
